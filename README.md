## About

The core idea behind MyWishlist: everyone manages their own gift wishlist, and can browse a friend's list to know what to get them. Adding a friend goes through a request system (send, accept, decline) — a friend's list only becomes visible once the relationship has been accepted on both sides, enforced server-side.

## Features

✅ Create, edit and delete gifts on your own wishlist
✅ Send, receive, accept or decline friend requests
✅ Browse a friend's gift list, once the friend request is accepted
✅ Edit your profile (name, avatar color)
✅ Secure authentication via JWT
✅ API documentation via Swagger

## Tech stack

### Backend (`mwl-backend`)
- **Bun** — runtime and package manager
- **Fastify 5**
- **TypeScript**
- **PostgreSQL** (via the `postgres` driver)
- **Drizzle ORM** + drizzle-kit
- **Zod** — request/response validation, via `fastify-type-provider-zod`
- **@fastify/jwt** — authentication
- **bcrypt** — password hashing
- **@fastify/swagger** + **@fastify/swagger-ui** — API documentation

### Frontend (`mwl-frontend`)
- **Bun**
- **Vue 3** + **TypeScript**
- **Vite**
- **Vuetify** — Material Design components
- **Pinia** — state management
- **Vue Router**
- **vue-i18n** — internationalization

## Architecture

The project is a monorepo (`mwl-app`) organized **by business feature**, on both the backend and frontend, rather than by file type. The root `package.json` doesn't use Bun workspaces — it just orchestrates the two sub-projects via `bun --cwd` scripts; each of `mwl-backend` and `mwl-frontend` has its own independent dependencies.

### Backend

```
mwl-backend/
├── drizzle/              # migrations generated by drizzle-kit
├── src/
│   ├── auth/             # signup, login, user profile
│   │   ├── contracts/        # Zod schemas (DTOs)
│   │   ├── controllers/      # Fastify routes + HTTP schemas
│   │   ├── errors/           # domain errors
│   │   ├── repositories/     # database access (Drizzle)
│   │   ├── services/         # mappers, utilities
│   │   ├── usecases/         # business logic
│   │   └── user.db.schema.ts # Drizzle schema for the users table
│   ├── database/          # Drizzle connection and configuration
│   ├── friends/            # friend requests, friend list, a friend's gifts
│   │   └── (same contracts/controllers/errors/repositories/usecases split)
│   ├── gifts/               # personal gift list
│   │   └── (same contracts/controllers/repositories/usecases split)
│   ├── plugins/             # Fastify plugins (db, auth, swagger, error handler)
│   ├── shared/               # cross-cutting code (AppError, shared error schemas)
│   ├── app.ts
│   └── index.ts
└── .envrc
```

### Frontend

```
mwl-frontend/
└── src/
    ├── features/
    │   ├── auth/              # login, signup, session
    │   │   ├── components/        # Login.vue, Register.vue
    │   │   ├── composables/       # useSignin, useRegister, useGetMe...
    │   │   ├── services/
    │   │   ├── stores/            # session.store.ts
    │   │   └── types/
    │   ├── friends/            # friends, requests, friends' gifts
    │   │   ├── components/        # addFriendDialog.vue, receivedRequestsDialog.vue...
    │   │   ├── composables/
    │   │   ├── presentation/      # FriendsView.vue
    │   │   ├── services/
    │   │   ├── store/
    │   │   └── types/
    │   ├── gifts/               # personal gift list
    │   │   └── (same components/composables/presentation/services/stores/types split)
    │   └── profil/               # profile page
    │       ├── components/
    │       └── presentation/      # ProfilView.vue
    ├── layout/
    ├── plugins/                  # i18n, pinia, vuetify
    ├── router/
    └── shared/api/
```

Each feature follows the same convention: business logic isolated in `usecases` (backend) / `composables` (frontend), data access in `repositories` / `services`, shared state in Pinia stores on the frontend.

## Installation

### Prerequisites

- [Bun](https://bun.sh) >= 1.0
- PostgreSQL >= 12
- [direnv](https://direnv.net/) (to load the `.envrc`)

### Steps

1. **Clone the repo**
```bash
git clone https://github.com/maximcharnallet/mywishlist.git
cd mywishlist/mwl-app
```

2. **Install dependencies** (each sub-project manages its own):
```bash
cd mwl-backend && bun install && cd ..
cd mwl-frontend && bun install && cd ..
```

3. **Environment variables** — create a `.envrc` at the root of `mwl-backend`:
```bash
export DATABASE_URL=postgresql://user:password@localhost:5432/mywishlist
export JWT_SECRET=your_jwt_secret
```
Then allow it:
```bash
direnv allow
```

4. **Database** — generate and run the Drizzle migrations:
```bash
cd mwl-backend
bunx drizzle-kit generate
bunx drizzle-kit migrate
```

## Usage

From the `mwl-app` root, using the workspace scripts (run each in its own terminal):
```bash
bun run dev:backend
bun run dev:frontend
```

- Frontend: `http://localhost:5173`
- Swagger API docs: `http://localhost:3000/documentation` (adjust the port if yours differs)

### Build

```bash
bun run build:frontend
```
The backend has no dedicated build step yet — it runs directly via Bun (`bun run dev:backend`); add a production start script if you need one for deployment.
